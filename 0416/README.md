# i-node와 데이터 블록

## i-node (Index Node)

i-node는 파일의 메타데이터를 저장하는 구조이다.

파일 이름을 제외한 파일의 주요 정보들이 저장되며 다음과 같은 내용을 포함한다.

* 파일 크기
* 파일 권한 (rwx)
* 소유자 정보
* 생성 및 수정 시간
* 데이터 블록 위치
* 링크 수

리눅스에서 파일이 생성되면 해당 파일에 대한 i-node가 함께 생성되며, 운영체제는 i-node를 통해 실제 데이터가 저장된 위치를 찾아 접근한다.

---

## 데이터 블록 (Data Block)

데이터 블록은 파일의 실제 내용이 저장되는 공간이다.

텍스트 파일이라면 문자 데이터가 저장되고, 이미지 파일이라면 이미지 데이터가 저장된다. 파일 크기가 커질수록 더 많은 데이터 블록이 필요하게 된다.

---

## 블록 주소 관리 방식

### 직접 블록 (Direct Block)

i-node 내부에 데이터 블록의 주소를 직접 저장하는 방식이다.

* 작은 파일 저장에 적합
* 데이터에 바로 접근 가능
* 가장 빠른 접근 속도 제공

### 간접 블록 (Single Indirect Block)

i-node가 데이터 블록을 직접 가리키는 대신, 데이터 블록 주소들을 저장하는 별도의 블록을 가리키는 방식이다.

* 더 큰 파일 저장 가능
* 주소를 한 번 더 참조해야 함
* 직접 블록보다 접근 속도가 느림

### 이중 간접 블록 (Double Indirect Block)

i-node가 간접 블록을 가리키고, 해당 간접 블록이 다시 다른 간접 블록을 가리키는 구조이다.

* 매우 큰 파일 저장 가능
* 여러 단계의 참조 과정 필요
* 접근 속도가 상대적으로 느림

### 삼중 간접 블록 (Triple Indirect Block)

이중 간접 블록을 한 단계 더 확장한 구조이다.

* 매우 큰 용량의 파일 저장 가능
* 참조 단계가 많아 접근 속도가 가장 느림

---

## 정리

파일 시스템은 파일 크기에 따라 저장 방식을 확장한다.

직접 블록 → 간접 블록 → 이중 간접 블록 → 삼중 간접 블록

작은 파일은 빠르게 접근할 수 있도록 직접 블록을 사용하고, 파일 크기가 커질수록 더 많은 데이터 블록을 관리하기 위해 간접 블록 구조를 활용한다.
